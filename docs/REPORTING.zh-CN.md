# 怎么写我们这样的报告

样例：
- [完整版（29 页）](../reports/full_study/BUA_brief_full_zh.pdf)
- [两页摘要](../reports/full_study/BUA_brief_onepage_zh.pdf)
- [ETTh1 快速版自动生成的初稿](../reports/example_etth1_quick/)

先翻一遍完整版，再读下面的规矩。

## 1. 两份东西

- **摘要（1–2 页）：** 给忙的人。依次是：
  - 问题；
  - 一句话答案；
  - 两张主表（热力图）；
  - 几条要点；
  - 待讨论。

  第二页可以放补充实验。
- **完整版：** 给要细看、要追问的人。所有定义、例子、表格、局限都在里面。

## 2. 完整版的结构

| 部分 | 写什么 |
|---|---|
| 开头 | 研究问题（一段话）；一句话结论；4–5 条要点，每条带数字和表号；还没回答的问题；状态行（哪些是新跑的、哪些是整理已有结果、结果截至哪天、这一版新增了什么） |
| 第 1 节 设计 | 一张示意图：在时刻 t，两个模型各看到什么。几种比较各回答什么问题 |
| 第 2 节 实验设置 | 数据、划分、模型、方法、训练预算、因果规则、怎么打分；“一组配对”的定义，带一个具体例子 |
| 结果各节 | 每节回答一个问题：先“怎么读”，再表或图，再要点。表和图都编号 |
| 补充实验 | 每个小节固定写：为什么做、怎么做、事先写好的判断线、怎么读、表、结果、猜测、要小心 |
| 结论 | 两栏：能说（在这次的范围内）/ 还不能说（数据撑不住的、范围外的、只是猜测的） |
| 讨论 | 要一起商量的问题，每个问题带上已有的证据 |
| 附录 | 背景研究、范围的变化、数据处理、术语表 |

## 3. 写法的规矩

这些都是我们吃过亏以后定下来的。

1. **先给答案，再给证据。** 开头一句话就回答问题，后面的节用表格支撑它。
2. **每个百分比都说清跟谁比、正负是好是坏。**
   - 写“在线误差比冻结低 7.4%”，不要只写“+7.4%”。
   - 负得很大的数换成倍数，例如 −250% 就是“在线误差是冻结的 3.5 倍”。
   - 拿两个参照比时，每一句都点名参照（“对调参后的冻结”“对主表的冻结”）。
3. **每个术语第一次出现就给定义和一个具体例子。** 例如收益、一组配对、倍率、预热。内部说法要翻译成人话：“倍率 1”要写成“不调小，就是主表的做法”。
4. **用中位数，同时给组数。** 写成“k/n”，即 n 组里在线更好的组数。训崩的极端值单独说，均值只当提醒。
5. **所有节、表、图都编号，正文用编号指。** 写“见表 7”，不要写“上面那张表”。改版时已经发出去的编号尽量不动；新表往后编，实在要挪就在状态行说明。
6. **点名，不说模糊的话。** 不写“变量多的数据集”，写“Weather（21 个变量）、Solar（137）、PEMS08（170）、Electricity（321）、PEMS-BAY（325）”。
7. **能说的和还不能说的分开。** 猜测要标“猜测”，并写出怎么检验；一个结论只靠一条运行的，要说出来。
8. **判断线事先写好再跑。**
   - 结果出来以后，照实说成立还是不成立，不事后挪线。
   - 事后加算的比较，注明“不在事先写好的判断线里”。
   - 判断线没写清的地方（比如没说用哪个参照），要说明你按哪种读法、换一种读法会怎样。
9. **写清范围。** 哪些数据集、哪些窗口、哪个预测长度、几个种子；结论只在这个范围内成立。
10. **不跨划分比较绝对误差。** O、T 的测试期和训练量都不同，只比同一划分里在线对冻结的相对差。
11. **新结果改变了前文，前文要跟着改。**
    - 例如“已在计划中”要改成“见 8.7 节”；
    - 之前写错的地方要改掉；
    - 别的内容不要顺手破坏。
12. **说法中性。** 不夸大，不用“显著”“大幅”这种没有数字支撑的词。给老师、同事的材料不用客套话，有分歧的地方写“待讨论”。
13. **给同学看的报告只讲科学。** GPU 小时、作业号、集群名这些工程细节不写。每个结果后面跟一句解释或猜测。
14. **实验状态如实写。**
    - “已安排”只在真的提交了以后才写；
    - “排队中”不说成“在跑”；
    - “跑完了”不等于“结果核对过”。
15. **数字不手抄。** 正文里的每个数都由脚本从结果文件生成，脚本里还要断言（`assert`）每个写进正文的数。数据一变，断言会提醒你哪句话要改。
16. **发之前找一个没参与的人冷读一遍。** 也可以让 AI 审读。专门找这几类问题：
    - 跟谁比没说清；
    - 前后矛盾；
    - 过时的说法；
    - 没定义的词；
    - 写过头的结论。

## 4. 从初稿到成稿

1. **跑完实验。** `python -m olts.run <配置>` 会生成：
   - `results/summary.json`；
   - `results/report_zh.html`（初稿：所有表格、编号和逐格句子都填好了）。
2. **核对数字。** 复现研究的设置时，运行 `python scripts/compare_with_study.py runs/<名字>`。
3. **写结论和解释。** 一句话结论、要点、“能说 / 还不能说”、猜测，每条都指向表号。
4. **把数字交给代码。** 复制 `olts/report.py`，在里面加你的段落：
   - 数字用 f-string 从 `summary.json` 里取；
   - 每个数加一句 `assert`。
5. **冷读。** 对着下面的清单查，或者请人读。
6. **出 PDF。** 运行 `bash scripts/html_to_pdf.sh <报告.html>`，然后检查分页：表格不要跨页，标题不要落在页底。

## 5. 发出前的检查清单

- [ ] 一句话结论能被主表直接支持吗？
- [ ] 每个百分比都说了跟谁比、正负是好是坏吗？
- [ ] 每张表、每张图都有编号、“怎么读”、组数吗？
- [ ] 每个第一次出现的术语都有定义和例子吗？
- [ ] 范围（数据集、窗口、H、种子）写清了吗？
- [ ] 猜测都标了吗？“能说”和“还不能说”分开了吗？
- [ ] 有没有过时的说法？“计划中”的事是不是已经做了？
- [ ] 数字都来自脚本、断言都通过了吗？
- [ ] PDF 分页正常吗？
