# 新同学练习：小范围跟跑

这份任务书带你用两周左右做四件事：

1. 在自己的 GPU 上把研究的协议跑通，并确认分数和研究一致；
2. 弄懂协议里每条规则为什么这样定；
3. 自己做一个小扩展：先写判断线，再跑；
4. 按我们的写法交一份报告。

**需要：** 1–4 张 A100 40G（一张也能做完，只是慢一些）。

**开始前先读（约 2 小时）：**
- [入门引导](CONCEPTS.zh-CN.md)：传统预测和在线预测差在哪。跟着跑完三个演示，做完第 7 节的自测题；
- [README](../README.zh-CN.md)；
- 两页摘要 [BUA_brief_onepage_zh.pdf](../reports/full_study/BUA_brief_onepage_zh.pdf)：知道研究在问什么、目前的结论是什么；
- [上手指南](GUIDE.zh-CN.md) 第 1–5 节。

## 任务 0：装环境，跑冒烟测试（半天）

照 [上手指南](GUIDE.zh-CN.md) 第 1–3 节做：

```bash
python -c "import torch, olts.engine; print('OK, CUDA available:', torch.cuda.is_available())"
bash scripts/download_data.sh ETTh1
python -m olts.run configs/smoke.json --jobs-per-gpu 4
```

**交付：**
- 第一行命令的输出，必须是 `OK, CUDA available: True`；
- 冒烟测试输出的最后几行，必须是 `0 failed`。

## 任务 1：复现 ETTh1 快速版（半天；一张卡约 15 分钟）

```bash
python -m olts.run configs/etth1_quick.json --jobs-per-gpu 4
python scripts/compare_with_study.py runs/etth1_quick
```

对照脚本最后一行应该是 `22 of 22 TEST runs have a study counterpart; |difference| median 0.0000%, largest 0.0000%`：你的 22 条测试流和研究的分数一致。我们在 RTX A5000 上实测，最大相对差是 4 × 10⁻⁷。差到百分之一以上，说明环境或数据不一样，先查清楚再往下做。

**交付：** 对照脚本的最后一行，加上下面 5 个问题的回答（每题一两句）。

1. 选中的学习率是多少？是怎么选出来的？（看 `runs/etth1_quick/selections/lr.json`）
2. 为什么 O 划分没有 W2048、W4096？
3. “冻结 W96”和“Naive-frozen”测试期都不更新，两者有什么区别？
4. 预测 96 步时，u 时刻发出的预测，什么时候评分、什么时候能拿来更新？
5. 按[写法规矩](REPORTING.zh-CN.md)第 2 条，写出你报告表 1 里“O 划分 · ER 对冻结 W1024”这一格的句子。

<details>
<summary>参考答案（自己答完再看）</summary>

1. 1e-4，两种划分都是。种子 2024 的模型在每档窗口里，按验证集 MSE 给 1e-4、3e-4、1e-3 排名，取跨窗口平均名次最好的（平局取小）。所有窗口、所有种子、在线模型都用它。
2. 训练起点要给每档窗口留至少 1,024 个训练样本。O 划分训练段只有 2,880 行，窗口 W 要满足 2,880 − 96 − W + 1 ≥ 1,024，即 W ≤ 1,761，所以最长到 W1024。
3. 冻结 W96 只做离线训练，部署后从不更新。Naive-frozen 是同一个在线模型：先预热，也就是在验证期每步更新、不发预测，到测试开始那一刻复制一份、之后冻结。它的起点和在线模型完全一样，所以“在线对 Naive-frozen”只看测试期继续更新本身的作用。
4. 在 t = u + 96 时，这 96 个真实值全部到齐：先给这个预测评分，再用这个样本更新在线模型，然后发出新的预测。
5. “O 划分 · ER 对冻结 W1024：在线误差比冻结低 5.3%（1 组里 1 组在线更好）。”快速版只有一组配对，所以只能说这一组，不能说“普遍更好”。

</details>

## 任务 2：ETTh1 学生版（1–2 天；四张 A100 约 1–2 小时）

这一步把主实验在 ETTh1、预测 96 步上跑过的全部内容做一遍：DLinear 和 PatchTST，3 个种子，两种划分。

```bash
python -m olts.run configs/etth1_student.json --gpus 0,1,2,3 --jobs-per-gpu 2
python scripts/compare_with_study.py runs/etth1_student
# 用研究的分数出同一范围的表，和你的表对照
python -m olts.analyze --streams results/full_study/streams_main.csv --where dataset=ETTh1 --where H=96 --out runs/study_etth1_h96
python -m olts.report --summary runs/study_etth1_h96/summary.json --lang zh
```

PatchTST 的在线测试流比 DLinear 慢得多：我们在一张 A5000 上同时跑 4 个 PatchTST 作业，O 划分 8 条流用了约 20 分钟。所以 PatchTST 每张卡最多放 2 个作业，宁可多用几张卡。

研究在 ETTh1、预测 96 步上也是这两个骨干、三个种子，所以两份报告的表 1、表 2 每格都是 6 组配对，应该几乎一样。DLinear 我们只在种子 2024 上实测过，和研究一致；PatchTST 我们只验证了能跑通，没有跑满 50 轮去对分数。另外两个种子和 PatchTST 的差别可能大一点，有差别要如实写出来。

**交付：**
- 你的报告初稿 `runs/etth1_student/results/report_zh.html`；
- 对照脚本的最后一行；
- 下面 4 个问题的回答。

1. 在 ETTh1 上，O 划分和 T 划分的结论一样吗？各举一格，按写法规矩写成句子。
2. 看同起点副本那张表：测试期继续更新本身有没有用？哪种方法最明显？
3. 有没有训崩的运行（误差超过冻结 10 倍）？在哪张表能看到？
4. 每次预测，在线比冻结 W96 慢几倍？

   注意：用时受 GPU 型号和同一张卡上同时跑几个作业影响。我们在一张 A5000 上同时跑 4 个作业，测出来是 5–13 倍；研究是每卡一个作业，测出来是 3.9–7.2 倍。要比用时，就用 `--jobs-per-gpu 1` 单独跑，并在报告里写明是怎么测的。

## 任务 3：一个小扩展（2–3 天）

**先写判断线，发给导师看过以后再跑。** 从下面选一个。推荐先做 A 或 B：研究里跑过同样的配置，跑完能用对照脚本核对。有余力再做 C 或 D：这两个是研究没在 ETTh1 上做过的新问题。

| | 做什么 | 配置 | 用时（参考） | 能和研究对照吗 |
|---|---|---|---|---|
| A | 换一个数据集：ETTh2（和 ETTh1 一样大），或 ETTm1（15 分钟一个点，长 4 倍） | `configs/etth2_quick.json`、`configs/ettm1_quick.json` | ETTh2 约 15 分钟；ETTm1 一张卡约 1 小时（估计） | 能 |
| B | 预测 336 步 | `configs/etth1_h336_quick.json` | 约 15 分钟 | 能 |
| C | 调小在线学习率：倍率从 0.03、0.1、0.3、1 里在验证集上挑 | `configs/etth1_small_lr.json` | 一张卡约 40 分钟（估计） | 不能 |
| D | 冻结也认真调参，再比长窗口在线 W1024 | `configs/etth1_tuned_w1024.json` | 一张卡约 30 分钟（估计） | 不能 |

建议自己先写配置，再和 `configs/` 里的参考版对一下。窗口和训练起点对齐窗口（`common_W`）怎么定，见[实验协议](PROTOCOL.zh-CN.md)第 5 节的表。

判断线写在 `runs/<名字>/PREREG.md`，**跑之前写好**，格式如下：

```
问题：（一句话）
比较什么：在线一方是……，参照是……，配对由……组成
范围：数据集、骨干、划分、H、种子
判断线（收益中位数；正数 = 在线误差更低）：
  ≥ 0：说明……
  ≤ −5%：说明……
  中间：不下结论
跑之前的猜测（可选）：
写于：日期和时间
```

A、B 的问题可以是“ETTh1 上的结论换到这里还成立吗”。判断线也可以写成数格子，例如“T 划分 15 个比较里，冻结更好的至少 12 个，就算成立”。

**交付：**
- 跑之前：`PREREG.md`；
- 跑之后：报告初稿；
- A、B 还要交对照脚本的最后一行。

## 任务 4：写报告（2–3 天）

交两份：
- 两页摘要；
- 完整版（PDF）。

内容是任务 2 的结果，加上任务 3 的扩展：事先写的判断线、结果、成立没成立。写法照[怎么写报告](REPORTING.zh-CN.md)；发之前过一遍那里的检查清单，再请一位没参与的同学冷读。

**要交的文件：**
- 报告的 PDF 和 HTML；
- 每次运行的 `runs/<名字>/spec.json` 和整个 `results/` 文件夹；
- 任务 3 的 `PREREG.md`。

`jobs/`、`data/` 不用交。

## 规矩

- **只在验证集上做选择。** 学习率、倍率、训练轮数都只看验证集；看过测试结果就不再改设置。
- **配置改了就换名字。** 失败的作业照实报告，不要只把结果不好的重跑一遍。
- **所有种子都报告。**
- **不跨划分比较绝对误差。**
- **遇到报错**，先看[上手指南](GUIDE.zh-CN.md)第 9 节，再问。问的时候附上 `runs/<名字>/logs/<作业>.log` 的最后几十行。
